# Review

- [fixed] correctness: taxa were keyed by name alone, so cross-kingdom homonyms (e.g. *Pieris* the plant genus and *Pieris* the butterfly genus, *Prunella*, *Morus*) were merged into one row, and a genus-only plant ID was dropped as "covered" by the butterfly species (src/checklist.rs:210, :301, :313) -> accumulator key now includes the iconic group; the leaf check requires the same kingdom (rank mode) or the same iconic group (no-rank mode). Tests `homonym_genera_in_different_kingdoms_stay_apart`, `homonyms_without_rank_columns_stay_apart`.
- [fixed] correctness: an ID at a rank with no export column (subgenus, section, complex …) got depth 0, so the genus-only ID above it still counted as an extra taxon, which is wrong under iNaturalist's leaf-taxon rule (src/checklist.rs:320-329) -> such taxa now sit just below the finest rank filled in their lineage. Test `identification_at_unlisted_rank_covers_its_genus`.
- [fixed] correctness: `name_key` turned GBIF-style hybrid names such as `Quercus ×bebbiana C.K.Schneid.` into `quercus`, so hybrids on a GBIF `--known` list were wrongly flagged NEW (src/input.rs:79) -> a leading `×` is stripped from each word. Regression assertion added to `name_key_strips_authorship_and_infraspecific`.
- [fixed] harm: the sensitive-taxa note only said "do not publish where on the property they were found", but the report already ties a threatened species to a named property, which is more precise than iNaturalist's obscured location. Organizers following the README could post the report and expose orchids and other collected taxa (src/render.rs sensitive-taxa paragraph, README Privacy) -> the note and the README now say to give the report only to the land manager and to remove sensitive names before publishing it. Test `sensitive_note_warns_against_publishing_names`. The listing stays because land managers need it.
- [fixed] honesty: README told users to "download a binary from the releases page", but no releases exist (README.md:32) -> it now says to build with Rust and that no prebuilt binaries are published yet. Install URL already matches `$FORGE_REPO_BASE/bioblitz-checklist`.
- [fixed] honesty: regenerated `examples/hilltop-report.{md,html}` so they match the new sensitive-taxa wording.
- [unfixed] correctness: a known list or export that is not UTF-8 (for example Excel's "Unicode text" UTF-16 or Windows-1252) fails with a clear error instead of being read. Adding encoding detection would be feature work, and the error does not produce a wrong report.
- [unfixed] correctness: a subgenus/section/complex ID still counts as its own taxon even when a species inside it was recorded, because the export has no column linking a species to its subgenus or section. This needs data the export lacks.

Checked and found fine: the 5,000-row performance claim (a synthetic 5,000-row export took about 0.02 s in a release build), deduplication across overlapping exports, casual/captive and research-only filters, BOM handling, the GBIF/iNat/plain `--known` formats, all flags documented in both `--help` and the README, and no usernames or coordinates in any output format.

Summary: the tool does what PROBLEM.md promises, end to end. It reads real-format iNaturalist exports and writes grouped, counted Markdown, HTML and CSV checklists with the leaf-taxon rule, highlights and `--known` comparison, so the verdict stays `build`. The main bugs were in the counting core. Taxa were identified by name only, so homonym genera in different kingdoms (common in mixed plant and insect bioblitzes) merged or hid each other. IDs at intermediate ranks let their genus be counted twice. GBIF hybrid names failed to match. Each fix has a regression test that failed before the fix. The one harm was mild: the report's privacy advice understated the risk of publishing names of sensitive taxa for a named site. The wording is now accurate. All four gates pass: fmt, clippy with `-D warnings`, test and audit.
